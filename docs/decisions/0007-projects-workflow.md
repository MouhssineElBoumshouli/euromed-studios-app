Status: built and live in the demo. Mouhssine to confirm the open points below.

## How a project moves
1. **Pre-production.** The owner adds at least one preparation file: a script, a rundown or a storyboard (R-22).
2. **Production.** Sessions booked "for this project" are linked to it (R-23). The project moves on once at least one linked session is validated or done (Q22).
3. **Post-production.** The technical team sets the editing status (P-07): not started → in progress → ready for check. The owner and collaborators can ask for corrections in the project thread (R-24).
4. **Quality check.** It's done by the technical team: régisseur, studio manager or admin (R-25, P-08).
   - **Pass:** the project is archived and the final file is delivered as a secure https link (Q12). This can't be undone, so the app asks for confirmation first.
   - **Fail:** the project goes back to "correction requested", and a reason is required.

## People
- The owner invites collaborators: requesters or régisseurs (R-27). The person must accept.
- There are at most 10 collaborators. Pending invitations count toward that limit.
- The owner can remove a collaborator, and a collaborator can leave.
- Studio staff can see every project and write in its thread.

## Notifications
- **Invitations:** go to the person invited.
- **Messages and corrections:** go to the project's people and to the team members working on the edit. If nobody is working on it yet, they go to the studio manager.
- **Quality checks waiting:** go to the same team members, and to the studio manager.
- **Project progress:** goes to the project's people.
